## 📖 这是什么

一个跑在 QQ 群里的**异步文字 RPG**：玩家在群里发指令，机器人把结果发回来；没人在线的时候，世界照样在走。

你在游戏里是一个具体的人 —— 有性别、年龄、出生地，有生命、灵性与理智。**从普通人开始**：没有途径、没有序列，路要自己碰出来，翻线索、凑材料、找配方，一步步走到序列 9、8、7。

三条隐藏的血条始终在动：

| | 含义 | 涨上去会怎样 |
| --- | --- | --- |
| 🧠 **疯狂**（MAD） | 精神磨损 | 到阈值会失控，做出自己控制不了的事 |
| ☣️ **污染**（COR） | 神秘学侵蚀 | 身体与认知一起走样 |
| 🧪 **消化**（DIG） | 对魔药的消化程度 | 不够就晋升不上去，硬升会出事 |

> 扮演法晋升：把「按这条途径的方式行事」写进日常，比反复刷同一句话更划算。

## 🚀 快速开始

### 环境要求

- **Node.js ≥ 22.18** —— 项目直接运行 `.ts`（依赖 Node 的类型剥离），数据库用内置的 `node:sqlite`，不需要编译原生模块
- 一条能收发消息的 QQ 机器人通道，三选一（见下方「接入通道」）

### 三步跑起来

```bash
# 1. 安装依赖
npm install

# 2. 准备配置（复制模板后填真值；.env 不会被提交）
cp .env.example .env

# 3. 启动
npm start
```

启动后：

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:3100/admin` | 运营后台 |
| `http://127.0.0.1:3100/health` | 健康检查与通道状态 |
| `http://127.0.0.1:3100/metrics` | 运行指标 |

### Windows 一键启动

双击 **`启动.cmd`**（或右键 `启动.ps1` → 使用 PowerShell 运行）：它会自检环境、缺 Node 就自动下载便携版、缺依赖就装、缺 `.env` 就从模板复制，最后把服务拉起来并打出后台地址。

```powershell
.\启动.ps1 -CheckOnly      # 只检查环境，不启动
.\启动.ps1 -SkipDownload   # 不自动下载 Node
```

## 🔌 接入通道

三条路的**玩法完全一样**，差别只在「怎么接 QQ」。用 `.env` 里的 `ADAPTER` 选。

### ① 内置正向 WebSocket（推荐）

```ini
ADAPTER=onebot
ONEBOT_WS_URL=ws://127.0.0.1:3001
ONEBOT_WS_TOKEN=
```

游戏自己连协议端（NapCat / LLOneBot / Lagrange 等）：事件从这条连接进来，发送也从这条出去。本机不用对协议端暴露端口，断线自动重连。

### ② 反向 HTTP 上报（老部署）

```ini
ADAPTER=onebot
ONEBOT_API_BASE=http://127.0.0.1:3000
ONEBOT_TOKEN=
```

协议端把事件 POST 到本机 `/onebot/event`，发送走协议端的 HTTP API。

### ③ QQ 官方机器人

```ini
ADAPTER=qq
QQ_BOT_APPID=你的AppID
QQ_BOT_SECRET=你的AppSecret
QQ_BOT_SANDBOX=1        # 沙箱环境填 1，正式填 0
QQ_BOT_MARKDOWN=1       # 只有 markdown 通道能显示图片
```

走 QQ 开放平台协议，不依赖 QQ 客户端，但需要机器人资质。两条通道一起挂：`ADAPTER=both`。

## 🎮 玩家指令

指令以 `.` 开头（例如 `.创建 曾经`）。**不用背** —— 每条回执末尾都会带上「下一步能做什么」，回数字即可。

### 上手

| 指令 | 说明 |
| --- | --- |
| `.创建 <姓名>` | 创建角色（会问一句性别，回 1 或 2）。出来的是**普通人**，还没有途径 |
| `.看` | 看自己在哪、周围有什么、能往哪走 |
| `.走 <地名>` | 走过去 |
| `.探索 <地点>` | 找材料（同一地点每日 3 次，小概率翻到配方线索） |
| `.今日` | 此刻还能做什么 |
| `.状态` | 文字状态卡 |
| `.角色` | 把角色画成一张图（通道发不出图时回落文字卡） |
| `.菜单 [编号]` | 图片版指令表 |
| `.帮助` | 怎么开始；`.帮助 faq` / `.帮助 规则` / `.帮助 公告` 看封测信息 |

### 角色与成长

| 指令 | 说明 |
| --- | --- |
| `.线索` | 手上有哪几张配方线索、主材料去哪里找 |
| `.图鉴 [神明/塔罗] [名字]` | 查神明与塔罗牌 |
| `.背包 [页码]` | 背包（区分绑定与非绑定） |
| `.装备栏` / `.装备 <物品>` / `.卸下 <物品>` | 装备 |
| `.使用 <物品> [数量]` | 用消耗品；封印物与符咒也走这条 |
| `.行动 <途径专属>` | 按途径的方式做事（拿到途径之后才有） |
| `.魔药 [配方]` / `.服用 [魔药]` | 调制魔药 / 服下魔药 |
| `.晋升` | 消耗消化度门槛与材料，序列 9 → 8（连续失败有保护） |
| `.仪式` / `.干扰` | 晋升仪式，以及插手别人的仪式 |

| 指令 | 说明 |
| --- | --- |

| `.查 [编号]` | 追查针对自己的阴谋 |
| `.教会` / `.加入教会` | 教会身份页与入教 |
| `.神战` | 看见神明的阴谋，并插手它（插手是会被发现的） |
| `.王座` | 空出来的位置怎么争 |

## 🔐 管理员指令

在群里就能管事，不用开后台。**只有名单里的人能用**（名单见下方「配置管理员」）。

完整清单发 **`.管理`** —— 那是一张专门画的管理员卡片菜单，分三张、带按钮翻页。

| 指令 | 说明 |
| --- | --- |
| `.封禁 @玩家` / `.解禁 @玩家` | 封掉一个人（他之后发什么都进不来）／放出来 |
| `.关闭游戏` / `.开启游戏` | 全服停／开 —— 关掉之后除管理员指令外一律不响应 |
| `.关闭本群游戏` / `.开启本群游戏` | 只作用在当前这个群 |
| `.关闭主动推送` / `.开启主动推送` | 世界在群里说话的总闸（灾厄与特殊事件的播报） |
| `.关闭本群主动推送` / `.开启本群主动推送` | 只静音当前这个群 |
| `.关闭主动事件推送` / `.开启主动事件推送` | 事件类的主动消息：灾厄播报，以及与玩家相关的私聊通知 |
| `.关闭本群主动事件推送` / `.开启本群主动事件推送` | 只作用于当前这个群 |
| `.游戏状态` | 三个开关的全局值与本群值 + 角色数 / 封禁数 / 群数 |
| `.世界状态` | 世界第几天、时段、月相、雾日、公共事件 |
| `.机器人状态` | 进程运行时长、内存、全服开关、管理员人数 |

几个约定：

- **「本群」类的指令要在群里发** —— 私聊里发会被拒绝，而不是悄悄变成全服操作。
- **本群没设过就跟随全局**；`开启本群…` 会把本群恢复成跟随全局。
- **管理员指令在游戏关闭时仍然可用** —— 否则关掉就再也开不回来了。
- 回执一律**只发给管理员本人**，群里不会刷屏。

### 配置管理员

两条路，取**并集**，两处都填也没关系：

| 在哪配 | 怎么填 | 什么时候生效 |
| --- | --- | --- |
| 后台「服务与访问」→ **管理员 ID** | 一行一个（也认逗号分隔），写 QQ 号 | 重启进程 |
| 机器人插件（`koishi` / `bee`）的设置页 | 同上 | 插件重载时自动上报给内核 |

也可以直接写进 `.env`：

```ini
ADMIN_IDS=10001,10002
```

> QQ 官方通道下，玩家 id 是 **openid** 而不是 QQ 号 —— 那种通道上要填 openid。

## 🛠️ 运营后台

浏览器打开 `http://127.0.0.1:3100/admin`（口令来自 `.env` 的 `ADMIN_PASSWORD`；不填则每次启动生成一个随机口令打进日志）。

- **玩家与存档**：查角色、改数值、发广播
- **内容编辑器**：途径、卡片、地点、势力、天气表……所有 YAML 内容表都能在后台增改，写回前经服务端校验
- **服务与访问**：监听地址、令牌、通道状态、登录审计
- **运维**：数据库备份与归档、日志查看、指标

## 📁 目录结构

```text
src/
├─ adapter/    通道适配器（OneBot / QQ 官方）—— 判定层不认识它们
├─ admin/      运营后台与内容编辑器
├─ card/       角色卡、菜单图与图片上传
├─ cards/      事件卡（内容，YAML，一个文件一张卡）
├─ data/       内容表（途径 / 势力 / 地点 / 物品 / 天气……）
├─ domain/     领域判定：纯函数，不碰数据库、不碰网络
├─ infra/      SQLite、时钟、日志、限流、备份
├─ router/     指令路由与每一条指令的实现
├─ sim/        模拟器与实测口径
└─ vplayer/    虚拟玩家回归（批量跑批、出报告）
bridge-api/    无适配器 / 纯 HTTP API 版，给 BEE、Koishi 这类上游框架对接
test/          全量测试
scripts/       运维、出图与回归脚本
```

## 🧱 设计要点

- **判定与通道分离**：`src/domain` 只做纯函数判定，`adapter` 是唯一的平台注入点 —— 所以同一份内核既能接 OneBot，也能接 QQ 官方，还能只开一个 HTTP 端口（`bridge-api/`）。
- **内容即数据**：新增一条途径、一个形态、一件封印物，都是往 YAML 里加一段，再由代码按字段解释；内容表在后台可视化编辑。
- **事件溯源**：角色状态由事件流推出，因果日志可回放、可审计。
- **单进程 + SQLite**：不需要额外中间件，一台机器一个进程就能跑。

## 🌿 分支说明

| 分支 | 内容 |
| --- | --- |
| **`main`**（当前） | 项目本体：单进程 Node 服务，直连 OneBot / QQ 官方 |
| **`bee-plugin`** | 项目本体 + BEE（Bee 官机框架）桥接插件：Go 版单 DLL 与易语言骨架 |
| **`koishi-plugin`** | 项目本体 + Koishi 插件 `koishi-plugin-lom-bridge`（内核随插件打包，装完就能玩） |

两个插件分支对接的游戏内核就是 `bridge-api/` —— 它不连任何平台，只开一个 HTTP 端口等上游来取。
